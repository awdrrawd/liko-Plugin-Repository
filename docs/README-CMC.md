# CMC v1.4.0

本輪修正保留既有 `/cmc` 指令與播放介面。

- **播放取消**：換歌、停止、關閉面板或離房後，舊音訊／影片載入回呼不再改動新的播放作業。停止時釋放預載音訊；歌詞請求可取消，舊歌曲的歌詞不會覆蓋新歌曲。
- **同步檢查**：用伺服器訊息的 Sender 核對 From，檢查房管、主控與播放／編輯權限。指定成員的歌單同步回覆有 10 秒接收期限。
- **同步播放**：以曲目 URL 保持歌單更新後的索引；載入完成後套用同步的暫停、音量與進度。Bilibili 訊息需來自目前的播放器 iframe。
- **資料保存**：IndexedDB 寫入等待交易完成，交易中止不會被當作成功；初始化逾時後才出現的連線會關閉。音量等設定合併延後 250ms 寫入，離房／停用時立即送出待保存設定。
- **歌單驗證**：名稱、URL 與清單格式會驗證；每份歌單最多 500 首，重複 URL 去重。匯入錯誤或空白歌單不覆蓋目前清單，成功匯入前將原清單保留到歷史。歌單仍沿用既有 IndexedDB 儲存位置，未改成依帳號分開。
- **介面**：面板拖曳支援滑鼠／觸控，不再覆蓋 `document.onmousemove`／`onmouseup`；對話框配合小螢幕限制寬高。
- **清理**：`window.Liko.CMC.Destroy()` 停止播放、恢復原 BC 音量、保存待寫入資料、取消事件與排程、卸載 SDK、關閉資料庫並移除 UI／載入旗標。`cleanup()` 仍是離房清理，不卸載整個插件。

一般儲存失敗會顯示提示，畫面中的未保存修改仍保留。歷史最多保存既有的 10 份房間歌單；成功匯入前的備份也受此限制。

驗證指令：`node scripts/test-cmc.cjs`。測試涵蓋完整腳本的登入前停用／重載、交易提交與失敗、逾時連線清理、訊息來源／權限，以及延遲播放取消。實際 YouTube／Bilibili 播放、房間多人同步與手機手感仍需遊戲內實測。
