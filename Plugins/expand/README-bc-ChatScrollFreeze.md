# BC_ChatScrollFreeze v1.4

向上捲動聊天紀錄時暫停插入新訊息，提供搜尋與待顯示訊息數量。回到底部、自己發話或呼叫 `unfreeze()` 會結束預覽。

## 長時間凍結

- 累積到 1,000 則待顯示訊息時自動結束預覽並追上最新，不以丟棄訊息處理容量問題。
- 回放每批最多 40 則，且每批約 8ms 後讓出主執行緒。單一原生 append 本身的耗時無法在中途打斷。
- 回放期間收到的新訊息排在既有佇列後方，維持順序；回放完成前暫停再次凍結。
- 聊天紀錄 DOM 被替換時，取消舊房間的待回放內容，避免插進另一個房間。
- 停用時同步清空目前房間尚未回放的內容，再移除攔截與計時器。

1,000 則是結束凍結的門檻，不是丟棄上限。如果訊息持續到達得比原生渲染更快，回放期間的佇列仍可能增長。

```js
const freeze = window.Liko.__Sys_ChatScrollFreeze__;
freeze.pendingCount(); // 尚未插入的訊息數
freeze.isReplaying(); // 是否正在分批回放
freeze.unfreeze(); // 開始回到最新；大量訊息時會分批完成
```

既有 `isFrozen()`、`openSearch()`、`mode()` 與 `teardown()` API 保留。
